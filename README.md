## 这是什么

一只在 Minecraft 里自己活着的小家伙（本项目里叫 **DeepSeek**）。
它不是"用脚本控制的机器人"，而是一个**分层大脑**：

```
                    ┌──────────────────────────────┐
   云 端 LLM ───────▶  大模型层 / 双向翻译器        │  听不懂的话 → 翻译成结构化动作
                    └──────────────┬───────────────┘
                                   │ fail-closed 校验（白名单 / 坐标 / 数量 / 宪法）
                    ┌──────────────▼───────────────┐
                    │  指令层（中文口令 → 结构化动作）│  规则优先，毫秒级，零成本
                    └──────────────┬───────────────┘
                    ┌──────────────▼───────────────┐
                    │  任务栈（多步任务 · 断点续跑）  │  看事实判完成，不看回执
                    └──────────────┬───────────────┘
                    ┌──────────────▼───────────────┐
   反射层 ★一票否决 ▶│  保命 / 挨打 / 逃跑 / 吃      │  <50ms，永远压过上面所有层
                    └──────────────┬───────────────┘
                    ┌──────────────▼───────────────┐
   热保护（温度红线）▶│  节拍器（1Hz / 5Hz 自适应）   │
                    └──────────────────────────────┘
```

- **脑**（`bridge.py`，Python，纯标准库）：反射层 / 任务栈 / 三觉 / 翻译器 / 心跳 / 记忆
- **手**（`node/server.js`，Node + mineflayer）：真去挖、放、合成、开箱子
- 两者之间用 **Unix Domain Socket + 一行一条 JSON** 通信，零额外依赖

### 设计上的三条硬规矩

1. **主链只放接线，新能力全部外置。** 主链 = `bridge.py` / `node/server.js` / `config.json`。
2. **fail-closed。** 听不懂、拿不准、参数缺 —— 一律拒绝执行并记账，绝不"猜一个动作出来"。
3. **手只报事实，脑才做判断。** 完成判据一律读探针事实，不认"命令发出去了"。

> 这三条和另外九条一起写在 **[`docs/开发宪法.md`](docs/开发宪法.md)** 里 —— 每一条后面都写着
> 它是**怎么踩出来的**。想接手这个项目，先读那一份。

## 车厢一览（19 节，M7b 之后长出来的）

### M7b 的特别之处（这个项目最有意思的一段）

要给脑侧加三种新动作，但**一个字都不许动主链**。做法：

```
外挂/动作面/
├── 大脑外挂.py     import bridge → 72 条锚点自检 → 看开关 → 打补丁 → bridge.主()
├── 补丁.py         运行时打补丁（monkey patch）：任务栈 3 个动作 + 指令层 3 条口令
│                   + 翻译器 prompt 包壳。**只改内存**，磁盘文件不碰。
├── 数据.py         外置数据加载 + 跟 minecraft-data / 主链 / 手侧三方交叉核对
├── 中文.py         中文语义坑的纯函数（附反例证明）
├── 自检.py         启动前逐条验锚点，少一条就**拒绝启动**
├── 测数据.py 56 条 / 测动作面.py 99 条     ← 含"反向测试"：故意喂坏数据看校验会不会报错
└── data/items_map.json + prompts/*.txt     ← 词表与 prompt 片段全部外置
```

**验收方式**（这个项目所有里程碑都这么做）：

```bash

sha256sum bridge.py                   # 2499f81f807431b0…
```

## 快速开始

> ⚠ 先装手侧依赖：`cd node && npm install`。
> 配方表**随仓库带了一份解析好的缓存**（`外挂/常识/缓存/原版配方.json`，265 KB），
> 所以**不需要** Mojang 的 `server.jar`（`runtime/` 那 50 MB 不在仓库里）。
> 跑一遍全部断言：`bash tools/跑全部.sh`（当前基线 **1132 条全过 / 0 失败**）。


```bash
# 脑：纯标准库，不需要装任何东西
python3 bridge.py

# 手：只依赖 mineflayer
cd node && npm install && node server.js
```

改之前先看 [`docs/开发宪法.md`](docs/开发宪法.md)，跑之前先跑六套回归：

```bash
python3 tools/测指令.py && python3 tools/测猎手.py && python3 tools/测任务.py
python3 tools/测三觉.py && python3 tools/测记忆.py && python3 tools/安全检查.py
```

> ⚠️ `config.json` 里的 RCON 密码、以及 `m3.llm.key_file` 指向的密钥文件，
> **都需要你自己改成自己的**。密钥文件刻意放在仓库外面，永远不会被提交。

## 关于皮肤

`assets/DeepSeek-skin.png` 是一张标准的 64×64 Minecraft 皮肤。

**但要如实说明**：在**原版离线模式（`online-mode=false`）服务器**上，
无头客户端**无法给自己的角色设置皮肤** —— 这不是实现问题，是协议层面的限制：

- 皮肤的 `textures` 属性是**服务端**在 `player_info` 包里下发的（`toClient` 方向只有一个）
- 离线模式下服务端不去会话服务器取皮肤，所以根本没有这个属性
- 客户端**没有任何 serverbound 包**能塞进自己的 `textures`
  （`client_information` 里的 `skinParts` 只管"显示哪几层"，不管贴图）

想真看到这张皮肤，需要其中一条：
1. 服务端换成 **Paper/Spigot + SkinsRestorer** 之类的皮肤插件；
2. 或者观看端装皮肤 mod（改的是看的人，不改服务端）。

素材已经放进仓库了，等哪天换了服务端直接就能用。
