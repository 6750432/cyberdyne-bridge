# M3 任务书草案 · 从「反射」到「听得懂话」

**起草**：大肥鱼　**日期**：2026-09-30
**状态**：等主人拍板，未开工

---

## 〇、先摆矛盾：M3 的全部设计都绕着这一条转

> **LLM 是个「慢的决策者」，而世界是快的。**

| | 延迟 | 代价 |
|---|---|---|
| 反射层（现在这套） | **< 50ms** | 0 |
| 本地 7B（Jan / Qwen 系） | **1~3 秒** | 占 ~4.4G 显存 |
| 云端 API | 0.5~2 秒 | 按 token 计费 |

**MC 里 1 秒可以挨 2~3 下打、掉 10 格血。**

所以 M3 的第一条铁律必须是：

> ### 反射层永远不能被 LLM 绕过，而且它有**否决权**。
> 主人喊「去打那个僵尸」的时候，如果小家伙只剩 3 点血，它**应该先跑**，
> 而不是先等 LLM 回话然后被打死。

这一条定不下来，M3 就会变成一个"很酷但一打就死"的玩具。

---

## 一、提议的架构：三层，越往下越慢、越贵、越可关

```
┌─────────────────────────────────────────────────────────┐
│ ① 反射层　Python · <50ms · 永远在线 · 零成本            │
│    跑 / 吃 / 保命 / 还手 / 迎战                          │
│    ← M1+M2 那一套，一个字不动                            │
│    ★ 有否决权：LLM 说破天也不能让它停止保命              │
├─────────────────────────────────────────────────────────┤
│ ② 指令层　Python · ~10ms · 纯规则模板 · 零成本           │
│    把主人的中文指令翻译成结构化动作                       │
│      「跟着我」       → {act:"follow", who:"mintstar"}   │
│      「去打那个僵尸」 → {act:"attack", type:"zombie"}    │
│      「他是我朋友」   → {act:"friend", who:"mintstar"}   │
│    ★ 覆盖率 80% 的日常指令，**一分钱不花**                │
│    ★ 匹配不上 → 记一条「听不懂」，才可能往下走             │
├─────────────────────────────────────────────────────────┤
│ ③ LLM 层　Python · 1~3s · 强限流 · **默认关**            │
│    只在两种情况下被调用：                                 │
│      a) 指令层模板匹配不上                               │
│      b) 反射层遇到"没写过规则"的局面                      │
│    ★ 输出必须是**从白名单里选的 JSON**，不是自由文本       │
│    ★ 不在白名单里的动作 → 直接丢弃 + 记一笔               │
│    ★ 关掉之后自动退回纯反射，系统照常跑                    │
└─────────────────────────────────────────────────────────┘
```

### 「动作白名单」是这套设计的关键

给 LLM 的提示词里**写死它能用的动作和参数范围**，它只能组合这些，不能发明新动作。

好处有三：
1. **输出可校验** —— 不在清单里就丢弃，不会出现"用钻石剑"（背包里根本没有）
2. **危险动作可以不给** —— 比如攻击默认不给 LLM，除非显式授权
3. **可测试** —— 白名单是有限的，能穷举验证

## 二、任务清单（按"该先做"排序）

### 任务 1 · 友好名单（还 M2 的欠账）　── 必做，最便宜

M2 实战里出现过两次「打中了「mintstar」！」——
现在靠 `hostile_players` 是空数组来回避，**但系统本身没有"这是自己人"的概念**。

- `config.json` 加 `friends: []`
- 名单里的人/宠物/村民**永不进入威胁列表**
- 自然语言可以动态加：「他是我朋友」「别打那只猫」

**验收**：把主人加进朋友名单，召唤僵尸，小家伙照打僵尸但**一次都不会碰主人**。

### 任务 2 · 指令层（零成本）　── 必做

- 主人在游戏里打字 → 手转发给脑 → 模板匹配 → 结构化动作
- 先覆盖 10~15 条最常用的：
  ```
  跟着我 / 别跟了 / 过来 / 站住 / 回家
  打那个 / 别打 / 打僵尸 / 停手
  吃 / 别吃了 / 血怎么样 / 你在哪
  他是我朋友 / 别打那只猫
  ```
- **设计要点：模板匹配不上时，不要瞎猜，老老实实记一条「听不懂：原文」**
  （这条记录就是任务 3 的输入）

**验收**：至少 10 条指令能用；说一句它没学过的，日志里出现「听不懂」而不是乱动。

### 任务 3 · LLM 层（可选，默认关）　── 想要，但危险

- **本地优先**：走 Jan 的 `127.0.0.1:1337`，白嫖已有模型，不烧云端 token
- **默认关闭**：`config.json` 里一个开关，关了就退回纯反射
- **强限流**：最短间隔 ≥10 秒，且每小时硬上限（防止死循环烧显卡）
- **显存保护**：接进现有的热保护；用完就卸（主人的红线）
- **校验器**：白名单 + 参数范围 + 前置条件（"有武器才能攻击"）
- **审计**：每一次 LLM 调用都记一条日志（问了什么、答了什么、执行了没、被否决了没）

**验收**：给它一句模板覆盖不了的话，它能给出一个**合法的**动作；
给它一句会让它送死的话，**反射层否决它**，并且日志里能看出是否决了。

### 任务 4 · 可回放测试台（工程账）　── 强烈建议

现在的验证方式太原始了：改一个参数 → 放僵尸 → 肉眼看日志。

- 把 `logs/实战记录-*.log` 变成**可重放的测试用例**
- 给定一串状态序列，喂给反射层，断言输出
- 做完之后，「改一个参数」能立刻知道会不会变差

**理由**：M2.1 那一轮，我改了 6 个参数，**全靠实机放僵尸验证**。
这在 M3 会彻底撑不住 —— LLM 的行为没法肉眼比对。

### 任务 5 · 任务分解（「帮我建个房子」）　── 建议放 M4

最诱人，也最容易变屎山。**M3 先不碰。**

## 三、我的建议：分两批

| 批次 | 内容 | 成本 | 风险 |
|---|---|---|---|
| **M3a（建议先做）** | 任务 1 + 2 + 4 | **0 token / 0 显存** | 极低 |
| **M3b（并行但默认关）** | 任务 3 | 可控（限流+开关） | 中 |
| M4 再做 | 任务 5 | — | 高 |

**理由**：任务 1、2、4 **不烧 token、不占显存、不会让项目变脆**，
而且任务 2 的「听不懂」记录正好是任务 3 的输入 —— 顺序天然是对的。

至于任务 3，我建议**做成插件式、默认关**：
它是"想要但危险"的东西，不该在没验证之前变成主链的一部分。

## 五、需要主人先定三件事

1. **LLM 用本地的还是云端的？**
   我倾向本地（不烧 token、不掉线），但它占 4.4G 显存、慢 1~3 秒。
   云端快一点但每次都要花钱，而且跟"小家伙应该能离线活着"这个理念冲突。

2. **LLM 允许有哪些动作？**（白名单）
   我倾向：**查询类随便给，移动类给一部分，攻击类默认不给**。

3. **「听不懂」的时候怎么办？**
   a) 老老实实说"我不懂"，原地待命
   b) 交给 LLM 猜
   c) 交给 LLM 猜，但猜错三次就永久禁言这条指令
