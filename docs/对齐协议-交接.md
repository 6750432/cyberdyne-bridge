## 二、协议（三条）

### 协议① 同一把时间尺
- 全链路一律用 **Unix epoch 毫秒**。
- 手侧状态帧盖 `t = Date.now()`（`node/server.js` 的状态包），与 `scan.t` 同尺。
- 判"新不新"一律 `Date.now() - t`，不再各算各的。
- 车厢里判扫描新旧：`_扫描多旧(s)`（返回秒；**测不出来返回 None，不许瞎拦**）。

### 协议② 盯梢是**合并**，不是覆盖
- 手侧 `watch_items` / `watch_blocks`：**给空列表 = 显式清空；`替换:true` = 仍旧覆盖；其余一律并集**。
- 这条是硬要求：主链"只盯这一次任务要的那几样"是天经地义，
  车厢"我要全量背包"也是天经地义 —— 谁后发谁说了算就会把先发的冲掉 ✗
- 车厢侧还有一层保险：`任务栈._挂探针` 被包了一壳，**每次挂探针都补发一次 `watch_items ["*"]`**。

### 协议③ 不许静默
- `_记账(...)`：缺字段 → **抛 ValueError**；类型不对 → **抛 TypeError**；
  写不进审计 → **出声报**（返回原因），绝不 `except: pass`。
- 这条对应主人清单里的 **T2「静默失败」**。

### ①.9 T2「静默失败」探测器 —— **已交付（回执探针车厢，顺序 85）**
车厢：`外挂/回执探针/` ｜ 测试：`外挂/测回执探针.py`（22 条）

**为什么要有它**：主人亲眼所见那次的日志里，手侧明明打了
`[探针-挖] …我手里没有镐子，挖不了 stone`（命令到了、手也拒了），
可大脑这边**一条「没做成」都没有**，只有 15 条「等了 60 秒还没成（超时）」——
说明手的回执**在路上丢了**，大脑只能干等到超时 ✗ 这就是 T2 的正身。

主链 `bridge.py:282` 的 `叙事者.看回执()` 本来写得好好的（成功念「成了」、
失败念「没做成：{why}」），所以这节车厢**只做两件事**、**不改行为**：
① 每一次「任务栈._下发」和「叙事者.看回执」都落一条 `logs/回执.jsonl`
  （发了多少 / 回了多少 / 丢了多少，事后能对帳）；
② 下发之后 N 秒（默认 8）还没回音 → **点名报警**：
  「★★ **回执丢了**：命令「dig」（步=挖@[9,9,9]）发出去 8 秒了，一点回音都没有」
  —— 「静默」从此是一条看得见的日志。

判据：只有**本来就该有回执**的才盯（走到/挖/放/合成/打/熔炉/箱子/递）；
「说」「等」「拾」不走 socket，**不计入**，免得自己造出误报。

**★ 写它的时候自己踩的两个坑（都留了断言）**
1. **「半个装上」**：第一版把 `_日志/_落路径/回执超时秒` 的赋值放在最前面，
   于是「故意让它失败」的那次调用虽然返回「好=False」，
   **却已经把超时线偷偷改成默认 8 秒** ✗ 后来那条 0.4 秒该报警的用例怎么也不响。
   规矩：**验齐了才动全局状态**，装上要么全做、要么什么都不做。
   → 断言 A6「装上失败时不许动全局设置」。
2. 测试里我**在装上之后才抓原函数**，于是 E2 断言 `卸下后 is 我抓的那个` 必然失败 ✗
   （抓到的本身就是包过的壳）。原函数必须在**装上之前**抓。
