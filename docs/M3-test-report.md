## 2. 做了四件事

### 任务 1 · 友好名单

**两道锁**（只靠一道不够）：

```
① 威胁判定里：朋友名单优先级最高，连算都不算
② 执行攻击() 里：再挡一次 —— 哪怕大脑下错了命令也打不出去
```

实测：
```
[23:21] 听懂了：「他是我朋友」→ friend（mintstar）
[23:21] 听懂了：「别打那只猫」→ friend（cat）
手侧 friends = ['mintstar', 'cat']
```

还顺手做了**口语名映射**：「别打那只猫」里的"那只猫"会翻译成 `cat` 才真的有用，
不然往名单里塞的是"那只猫"三个字，跟实体名对不上。

### 任务 2 · 指令层（零成本，纯规则）

覆盖 11 条：

```
跟着我 / 别跟了 / 过来           → follow / stop
他是我朋友 / 不是我朋友了         → friend / unfriend
别打那只猫 / 别打小明            → friend（带口语名映射）
去 10 70 5                      → goto
吃东西 / 血怎么样 / 停 / 打那个   → eat / status / stop / strike
```

实测全过程：
```
[23:21] 听懂了：「跟着我」→ follow（mintstar）
[23:21] 他动了，挪到 (0, 78, -4)（走了 5.0 格）
[23:21] 到地方了。离目标还有 2.2 格。          ← 用寻路插件真的走过去了
```

**关键设计：故意不猜。** 模板匹配不上就记一条「听不懂」，绝不自作主张：
```
[23:21] 「mintstar」说「今天天气真好」—— 这句我没学过，先老实说不会，绝不乱动。（听不懂第 1 条）
```

这条记录**就是大模型层的输入** —— 顺序天然是对的。

### 任务 3 · 可回放测试台

```
tools/录制.py 30              连上大脑录 30 秒原始状态
tools/回放.py 录像.jsonl --存 基准.json
tools/回放.py 录像.jsonl --对照 基准.json   # 一致退 0，有差异退 1
```

**时间处理是关键**：反射层用 `time.time()` 做冷却判断，
回放时如果按真实时间跑，144 帧会在几毫秒内过完，所有冷却都算作"刚触发过"，结果全错。
所以回放里装了一个**虚拟时钟**，按录像里的 `t` 字段推进。

实测（144 帧战斗录像，改 `counter_dist` 2.2→1.2）：
```
  各状态帧数：平静=88、迎战=55、反击=1
  ⚠ 和基准有 7 处不同（前 8 处）：
    #9  基准 {'状态': '反击', '命令': [{'cmd': 'attack', ...}]}
    #9  现在 {'状态': '平静', '命令': []}
    ...
  ▶ 退出码 = 1
```

### 任务 4 · 云端 LLM 层

**默认关。** 白名单**刻意不含攻击**：

```
follow / goto / say / stop / status / friend      ← 就这六个
```

校验器实测（不花钱的离线单测）：

| 大模型想干什么 | 结果 |
|---|---|
| `{"act":"follow","who":"mintstar"}` | ✅ 采纳 |
| `{"act":"attack","target":"mintstar"}` | ⛔ **「这不在白名单里，我拒了」** |
| `{"act":"mine","block":"diamond_ore"}` | ⛔ 同上 |
| `{"act":"self_destruct"}` | ⛔ 同上 |
| 跟一个看不到的人 | ⛔ 「可我看不到这个人」 |
| 跑 707 格开外 | ⛔ 「太远了」 |
| 根本不是 JSON | ⛔ 丢弃 |

**真调用实测**（就花了两次，省 token）：

```
「跟紧我，别走丢了」                 ← 模板匹配不上
→ 大模型翻成 follow，who=mintstar    ← 提示词里写清楚"谁在说话"
→ 它照着走过去了

「帮我把那片树叶摘下来」              ← 白名单里没有这个能力
→ 大模型翻不出来 → 它输出 {} → 丢弃
→ 「大模型也没翻出来 —— 那我不动。」  ← ★ 没有瞎编
```

**限流实测**：第 1 次放行，第 2~5 次全部「拒绝 —— 离上次不到 10 秒」。
**审计**：每次调用都写进 `logs/llm审计.jsonl`（问了什么、答了什么、采纳没采纳、为什么）。

**密钥安全**：密钥放在 `~/.config/cyberdyne-bridge/key`（权限 **600**），
**绝不写进 `config.json`** —— 免得哪天配置被分享出去的时候一起漏了。
实测 `grep -c 'sk-' config.json` = **0**。

## 4. ⭐ 回放工具上岗第一小时就回本了

它抓出一个**藏了两轮的静默 bug**：

```python
# bridge.py 主循环
反射 = 反射层(m1, 说)        # ← 只喂了 m1
```

**而 M2 的全部参数都在 `m2` 里** —— `counter_dist`、`finish_hp`、
`counter_cooldown_ms`、`announce_delta`、`empty_bag_hp`……
它们的读法是 `self.m.get("counter_dist", 3.0)`，
`self.m` 里根本没有这些键，于是**永远返回代码里的硬编码默认值**。

### 后果

**我在 M2.1 里改的那一行 `counter_dist: 3.0 → 2.2` 从来没生效过。**
它一直用的是 3.0。

M2.1 那次命中率从 18% 涨到 100% 是**真的**，但那来自 `停步才挥` 的**代码改动**，
跟那行配置**一点关系都没有**。也就是说：

> 我写了一份看起来很精确的配置表，其中**五六个数字是死的**，
> 而且**没有任何东西会报错** —— 代码不报错、日志不报警、测试也过。

### 怎么发现的

给回放工具做"改参数能不能抓到差异"的自测时，
我把 `counter_dist` 从 2.2 改成 1.2，回放结果**完全一致**。
正常反应是"录像里没触碰到这段逻辑"，但我多看了一眼 ——
录的那段里明明有 `反击` 帧，距离就在 2.2 附近，改成 1.2 不可能一样。
顺着这条线才挖到 `反射层(m1, ...)` 这一行。

### 修法

```python
# 主链：反射层要同时拿到 m1 和 m2
反射 = 反射层({**m1, **m2}, 说)
# 回放工具也必须跟着改，否则它测的是一个和线上不一样的东西
```

修完之后重跑同一段录像：`反击` 帧数从 **4 变成 1** —— 说明配置真的生效了
（2.2 比原来的 3.0 严格，出手更谨慎）。

### 这条教训值多少

这是 M2 报告里我推荐的"任务 4 可回放测试台"的**第一次实战回报**。
它的价值不在于"能跑测试"，而在于：

## 5. 踩到的坑

| # | 坑 | 教训 |
|---|---|---|
| 1 | **`反射层(m1)` 漏了 m2** —— 配置静默失效 | 见第 4 节。**"没报错"不等于"生效了"** |
| 2 | 引号打架：外层 `"""` 内层也是 `"""`，插入的 docstring 把外层字符串提前截断了 | 嵌套字符串换一种引号 |
| 3 | 「不是我朋友了」被「我朋友」先匹配走了 | 规则表里**否定句必须排在肯定句前面** |
| 4 | `for 话 in ...` —— bash 中文变量名非法 | 老毛病，第 N 次。**bash 里一律 ASCII** |
| 5 | XTest 打不出中文（没有输入法驱动） | 测指令层改用 `execute as <玩家> run say <中文>` |
| 6 | Cherry Studio 的 `api_keys` 是**字典列表**不是字符串列表 | 结构得先探明再取值 |

## 6. 没做 / 待改进

### ① 任务 5（任务分解）按计划没做
「帮我建个房子」这类需求，M3 明确不做，留给 M4。

### ② LLM 层的坑还没踩够
- **只测了两次真调用**，样本太小
- **没有测过它乱输出的时候会不会把状态机搞乱**（校验器单测过，但没在真流程里灌过脏数据）
- **每小时 40 次封顶没实测过**（单测过逻辑）

### ③ 指令层只认整句，不做分词
「你能过来一下吗」这种带语气词的可能匹配不上。**目前够用，先不过度设计。**

### ④ 回放基准还是手录的
没有"自动收集回归用例"的机制。每次要新场景，得手动录一段。

### ⑤ 危险动作也只是"不给白名单"
白名单之外没有第二道校验（比如 `say` 只限了长度，没限内容）。
**如果哪天要把攻击类动作开给 LLM，得先补一层"内容审查"。**
