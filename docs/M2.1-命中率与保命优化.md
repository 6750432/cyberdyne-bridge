# M2.1 · 命中率与保命优化

**触发**：主人看完实战复盘后给的指令 —— 「**怎么攻击效率最大化又能保命就怎么来**」
**日期**：2026-09-30 22:45 – 23:05
**前提**：M2 的功能与防线一个都不动，只调战术

---

## 一、成绩对比（同一只僵尸、同一个场地）

| 指标 | M2 实战（优化前） | **M2.1（优化后）** |
|---|---|---|
| 打死一只僵尸要挥几下 | 67 挥 · 只中 12 下 | **4 挥 · 4 中** |
| **命中率** | **18%** | **≈100%** |
| 自己挨打 | 16 下 / 合计 45 点伤害 | **0 下 / 0 点** |
| 自己的血 | 掉到 **0.2 / 20**（差点死） | **始终 20 / 20** |
| 杀怪耗时 | — | **20 秒**（5 秒 / 10 秒 / 15 秒各中一下） |

实测曲线（僵尸血量随时间的读数）：

```
第  5 秒：剩 14.096 血   ← 第一下，-5.9
第 10 秒：剩 14.096 血   ← 没挥（在走位）
第 15 秒：剩  8.192 血   ← 第二下，-5.9
第 20 秒：（无）         ← 第三下，死
```

## 二、根因：不是参数没调好，是**两个物理约束没有正面处理**

### 🔴 根因 1：边跑边挥 = 打不中

服务端判定攻击距离用的是**它自己那份位置**，而客户端位置更新滞后 50~100ms。
一个 4.3 格/秒的人在 100ms 里跑掉 **0.43 格** ——
报 2.5 格，服务端看到的是 2.9 格，正好卡在 3 格射程线上，于是大量挥空。

> **修法**：挥之前先 `停动作()` 站住，`await bot.lookAt()` 等转向发出去，
> 再等 100ms 让服务端同步，最后才 `bot.attack()`。

### 🔴 根因 2：逃跑速度和追击速度**一样**

走路 4.317 格/秒 = 追击同速。所以 M2 里那句「后撤 2 格」**在数学上等于没撤** ——
怪物一步就跟上来了，形成 2.5 格的僵持带（实测 76% 的出手都挤在那里）。

> **修法**：逃命一律**疾跑**（5.612 格/秒，快 30%），后撤时长 480ms → **1100ms**。

### 🟠 新问题（改完才冒出来的）：跑得太好，一次都打不着

疾跑一开，小家伙把僵尸甩到 **34 格外**。安全是安全了，**攻击效率归零**。

> **修法**：新增「**迎战**」状态 —— 打得过的时候**站着不动**，让对手自己走进打击圈。

## 三、新战术：三段式

```
敌人进 5 格
   │
   ├─ 能打得过（血>12 且 有武器 且 对面只有一个）
   │     ├─ 距离 ≥2.2 格  →  【迎战】站住不动，等它进来
   │     └─ 距离 <2.2 格  →  【反击】停步 → 转身 → 挥 → 疾跑撤 6 格
   │
   └─ 打不过（血≤12 / 没武器 / 对面人多）
         └─ 【逃跑】疾跑，不回头
```

「**站住等它进来**」是这一轮最关键的改动 ——
以前它一见到怪就跑，疾跑之后更是跑得没影；
现在是**在自己选定的距离上等对手送上门**，把「选择交战时机」的主动权拿了回来。

## 四、改了哪些数字

| 参数 | 旧值 | 新值 | 为什么 |
|---|---|---|---|
| `counter_dist` | 3.0 格 | **2.2 格** | 3.0 是射程边缘，实测大量落空；2.2 才是可靠命中距离 |
| `sprint_when_flee` | false | **true** | 同速追逃 = 后撤无效；疾跑才拉得开 |
| `counter_retreat_ms` | 480 ms（约 2 格） | **1100 ms（约 6 格）** | 「打完就跑」的"跑"要真的跑掉 |
| `counter_cooldown_ms` | 2500 ms | **1400 ms** | 突进更频繁，效率更高 |
| `finish_hp` | —（新增） | **7** | 对手血到一刀的量就补刀，不撤（撤了等于放走） |
| `announce_delta` | —（新增） | **0.5** | 宣告合并，治那 41 次一字不差的刷屏 |

## 五、顺手修掉的四个可观测性缺陷

| # | 问题 | 修法 |
|---|---|---|
| 1 | **成功挥击完全不留痕** —— 只看得到「它宣告要打」，看不到「打中没有」 | 新增 `entityHurt` 事件 → 大脑翻译成「打中了「僵尸」！」 |
| 2 | **`entityHurt` 不能直接当命中用** —— 挨打动画的元数据会重复推送，实测 7 次挥击刷出 28 条 | 加 400ms 时间窗：只有「我们刚挥完 400ms 内」才算我们的命中 |
| 3 | **紧急日志把正常日志饿死** —— 共用一个滑动窗口，战斗时「退两步」一条都记不下来 | **两套额度分开算** |
| 4 | **启动横幅吃光第一分钟的正常额度** | 给 `说()` 加 `不计流` 参数，横幅不吃额度 |

## 六、验证

单元自测（不连游戏，纯逻辑）：

```
僵尸 4.0 格 / 血 20   → 迎战      ← 站住等它进来
僵尸 2.5 格 / 血 20   → 迎战      ← 还在打击圈外，继续等
僵尸 2.0 格 / 血 20   → 反击      ← 进圈了，打
僵尸 2.5 格 / 血只 8  → 逃跑      ← 打不过，跑
```

实机单挑（僵尸血量实测）：**4 挥 4 中，自己 0 伤害，20 秒击杀**。

防线核对：烂包 **0** / 大脑内部意外 **0** / 热挂起 **0**。

## 七、还没做的 / 已知问题

1. **「谁是自己人」这个概念仍然没有** ——
   实测里出现了「打中了「mintstar」！」（主人当时站在 0.1 格开外被扫到）。
   好消息是 `hostile_players` 已清空，主人不再被当成威胁；
   但**「扫到旁边的人"这件事本身没有判断」**，这是 M3 该定的。

2. **`finish_hp` 补刀逻辑实测 0 次触发** ——
   因为测试用的僵尸血掉得比"补刀判定"更快（3 下一只，中间隔着寻敌间隙）。
   逻辑是对的，但**还没在真实场景里被验证过**。

3. **迎战状态在敌人 >5 格时会退出**，如果对手是远程（骷髅），
   「站着不动」可能反而是挨箭。**远程敌人还没区别对待。**

4. **疾跑的饥饿消耗没测** —— 16 块牛排撑多久不清楚。
