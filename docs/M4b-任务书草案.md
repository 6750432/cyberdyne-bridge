# M4b 任务书草案 · 腿·会绕路

> 一句话题目：**让它追人的时候会绕过障碍，而不是顶着墙挥空拳。**

## 为什么要做
M4 实测（2026-10-01）暴露出它只会**直线追击**：主人竖两块木板挡着，它就顶在墙上，
能打到的只是"隔墙那一拳"（那还是协议层的漏洞，已经堵掉了）。
换成有树、有沟、有门的世界，它基本追不到人。
而寻路插件 **早就在仓库里**（`node/plugins/pathfinder/`，可选挂载），
缺的只是「什么时候该交给它」这一层判断。

## 目标
1. 追人时遇到障碍能**绕过去**（优先交给寻路插件）。
2. 插件不在时**照样能绕**（土办法：沿墙滑），主链一行不炸。
3. 无障碍时**仍然走直线**——不为绕路付性能税。

## 验收点（都拿数据验，不靠肉眼）
| # | 场景 | 期望 |
|---|---|---|
| A | 主人在两格高的墙另一边 | 它绕过去并**打到**（日志/账本里有 `卡住`→绕行→命中） |
| B | 台阶 / 单方块挡路 | 不卡死（连续卡住→翻面绕行） |
| C | 拔掉 `node/plugins/pathfinder/` | 仍然能绕（土办法），主链与既有回归全过 |
| D | 空场追人 | **不触发**绕路（零 `卡住` 事件），走直线不变慢 |
| E | 回归 | `测猎手.py` / `测指令.py` / 回放基准 全过 |

## 怎么实现（三层）
- **手（事实）**：新增「卡住」这条事实 —— 每 250ms 看一眼：这一拍命令它往前走，
  它到底动了没有（位移 < 0.12 格 = 没动）。快照里给 `stuck_count`（只增不减的计数）
  和 `stuck_ms`（距离上一次卡住多久）。账本记一条 `卡住`。
- **脑（判断）**：`stuck_ms` 还新鲜（< 2.5 秒）就算"正卡着"。
  - 有寻路插件 → 每 1.2 秒把"目标当前位置"交给插件（`goto`），自己不抢方向盘；
  - 没有插件 → 土办法：把朝目标的直线方向**转 70°** 硬走（沿墙滑）；
    再卡住就**翻到另一边**（-70°），连续翻两次还卡就改 110°（退开一点绕大圈）。
- **配置**：`m4.detour_enable`（总开关，关掉即退回纯直线）、`detour_angle`、
  `detour_goto_ms`。

## 明确不动什么
- 反射层优先级（保命 ＞ 反击 ＞ 锁定）**不动**。
- 攻击 / 连击 / 跳劈 / 隔墙判定 **不动**。
- 主链动词表**不膨胀**（`goto` 早就有）。
- 不引入新依赖（寻路插件本来就是可选外挂）。

## 风险与红线
- `goto` 是长动作，期间挥不了拳 → **只在还没进打击圈时绕路**，进了圈就收回方向盘。
- pathfinder 计算量略大，但只在绕路期间跑；红线不变（CPU ≤ 60%、温度上限照旧）。
- 土办法可能"绕远路甚至绕丢" → 绕行只在被判定卡住时生效，不卡就是直线。

## 怎么回滚
`config.json` → `m4.detour_enable = false` → `bash tools/重启.sh`。
（代码改动集中在 `node/server.js` 的卡住检测和 `bridge.py` 的绕行状态机两处。）
