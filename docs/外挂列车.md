# 外挂列车 —— 副链外挂的热插拔与自由组合

> 2026-10-07 建。主人原话：「我的副链的那些外挂要可以像开火车那种随时都可以连/断的，
> 自由组合也行。」

---

## 一、它解决什么问题

在它之前，副链外挂只有 `外挂/动作面/` 一个入口 `大脑外挂.py`，动作面**焊死**在里面。
想加第二种本事，只能再写一个入口脚本，而且两个不能同时跑（抢同一个 socket）。

现在改成了**车厢模型**：

```
外挂/
├── 车钩.py              ← 车钩本体：发现车厢、编组、挂/摘/重排、宪法闸门
├── 车钩ctl.py           ← 遥控器：脑在跑的时候从另一个终端发命令
├── 启动列车.sh           ← 启动 / 重启 / 看状态
├── 测车钩.py             ← 离线测试（71 条）
├── 编组.json             ← 当前编组（自动存，下次起车照它挂）
├── 车钩.sock             ← 控制插座（0600，只在脑跑着的时候存在）
├── 动作面/               ← 第 1 节车厢（2026-10-01 的 M7b 外挂，一行没改）
├── 受限脚本/             ← 第 2 节车厢（2026-10-07 新做）
├── 任务书体检/           ← 第 3 节车厢（2026-10-07 新做）
└── 拒单反馈/             ← 第 4 节车厢（2026-10-07 新做）
```

**默认编组**（按 `顺序` 排）：`动作面(10) → 受限脚本(20) → 任务书体检(30) → 拒单反馈(40)`

**红线不变**：`bridge.py` 一个字节都没动，sha256 始终是 `2499f81f807431b0`。

## 二、车厢是什么

一个目录 + 两样东西：

**① `manifest.json`（铭牌）**

| 字段 | 说明 |
|---|---|
| `id` | 唯一名（默认取目录名）。重名会被拒绝启动 |
| `名字` | 给人看的长名字 |
| `版本` | 随便写，只是展示 |
| `入口` | 车厢本体，默认 `补丁.py`。**必须有 `装上()`，最好有 `卸下()`** |
| `自检` | 可选，自检脚本名 |
| `顺序` | 编组排序用。小的先挂 |
| `可热拔` | 默认 true。没有 `卸下()` 的车厢会被强制改成 false |
| `开关` | 可选，形如 `m7.expand_actions`。关 = 一个补丁都不打 |
| `依赖` | 必须排在我前面的车厢 |
| `冲突` | 不能和我同挂的车厢 |
| `提供动作` | ★ 我往 `任务栈.允许动作` 里加了哪些动作（**扩权申报**） |
| `补丁点` | 我动了哪些函数/属性（撞车会警告） |
| `实例缓存` | ★ 我在哪些类的**活实例**上留了缓存（见第六节） |

**② 车厢本体（`补丁.py`）**

标准接口，两条：

```python
def 装上(bridge, **要的) -> {"好": bool, "为什么": str, "打了": [str]}
def 卸下(bridge) -> bool
```

★ **车钩会先看函数签名，只传它认识的参数**（`数` / `开关` / `车钩` / `日志` / `临时目录`）。
所以老的动作面 `装上(bridge, 数=, 开关=)` 不用改一行就能上车。

**可选接口两条：**

```python
def 同步实例(bridge, 日志=None, 车钩=None) -> int     # 换轨后刷新活实例，见第六节
def 重挂后(...)                                        # （预留，暂未使用）
```

## 三、用法

### 起车

```bash
bash 外挂/启动列车.sh                            # 按 编组.json 起
bash 外挂/启动列车.sh --编组 动作面,受限脚本      # 指定这趟挂什么
bash 外挂/启动列车.sh --空车                     # 一节不挂，裸脑
bash 外挂/启动列车.sh --基线                     # 主链原入口（回退走这条）
bash 外挂/启动列车.sh --看                       # 只看状态，绝不动进程
```

### 热插拔（脑在跑着的时候）

```bash
python3 外挂/车钩ctl.py 编组                     # 看现在挂着哪几节
python3 外挂/车钩ctl.py 列                       # 列出磁盘上所有车厢（不用连脑）
python3 外挂/车钩ctl.py 挂 受限脚本               # 热挂
python3 外挂/车钩ctl.py 摘 受限脚本               # 热摘
python3 外挂/车钩ctl.py 摘 受限脚本,动作面         # 一次摘多节（原子）
python3 外挂/车钩ctl.py 重排 受限脚本,动作面       # 重新排序
python3 外挂/车钩ctl.py 验                       # 重跑宪法体检
python3 外挂/车钩ctl.py 记事                     # 换轨历史
python3 外挂/车钩ctl.py 查 动作面                # 看某节车厢的铭牌
```

实测：**换轨 1~7 毫秒**，脑不重启，手（node）不重连，小家伙在游戏里毫无感觉。

## 四、三个设计决定

### ① 换轨 = 全列重排，不做「车上拆钩」

补丁是 `setattr` 覆盖类属性。两节车厢如果动了同一处，精准逆向摘一节极易留下半截状态。
所以**摘一节的动作**是：

```
全部按逆序卸干净  →  从名单里划掉它  →  再按正序全挂回去
```

代价毫秒级，换来的是「当前状态永远可以从编组名单推导出来」——
不会出现摘不干净的幽灵补丁。

### ② 换轨必须先过闸，违宪就自己退回原位（fail-closed）

见第五节。

### ③ 主链的顶层对象不许被换掉

改类的属性 = 外挂；换掉 `bridge.主` 本身 = 改主链。
车钩在挂载前后各拍一张 `vars(bridge)` 的身份快照，
**任何顶层对象的身份（`id()`）发生变化就判违宪**。

这样「主链零改动」不再只是一句自觉。

## 五、宪法体检 —— 四条不变量

每次换轨后自动跑。任何一条不过 → **把旧编组原样挂回去**，然后报告失败。

| # | 不变量 | 防什么 |
|---|---|---|
| ① | `vars(bridge)` 里所有顶层对象的 `id()` 不变 | 防车厢把 `bridge.主` 换掉（= 真改主链） |
| ② | `任务栈.允许动作` ⊆ 基线 10 个 ∪ 各车厢申报的「提供动作」 | 防车厢**偷偷扩权**加动作 |
| ③ | `翻译器.单步白名单` ∩ `攻击类` = ∅，且白名单 ⊆ 基线 6 个 | 防攻击动作混进白名单（宪法第①条） |
| ④ | `翻译器.禁止步骤` 必须仍含「打」 | 防把宪法第②条摘掉 |

基线值硬编码在 `车钩.py` 顶部，抄自 `bridge.py:1371` 与 `bridge.py:2491-2493`。
**改主链就必须同步改这里，而且会红给你看** —— 这就是它存在的意义。

### 车钩的极限（诚实说明）

如果一节车厢「挂了坏事又不还」（`卸下()` 不还原），车钩**只能当场抓住 + 大声喊人**，
没法凭空把残骸清掉。它会：

1. 抓住违宪 → 退回原编组
2. 记住残骸还在 → 下一次体检照样报出来
3. 日志里写「现在车上是不确定状态，请重启脑」

**它不假装清掉了。** 这条由 `测车钩.py` 的 D5 组专门验。

## 六、★ 最阴的那个坑：活实例拿着旧缓存

**这是热插拔能不能真生效的关键，不解决的话整套东西就是个摆设。**

`翻译器.合法步骤` 是在 `__init__` 里存的**实例属性**：

```python
# bridge.py:2503
self.合法步骤 = set(允许动作)
```

也就是说，往一个**正在跑的**脑上热挂「动作面」时：

- 类属性 `任务栈.允许动作` → 扩了 ✅
- **已经建好的那个翻译器** → 还拿着旧的 10 个动作 ❌

模型写「合成」，翻译器会把它扔掉。主人看到的现象是
**「你说开了，可它还是不会合成」** —— 本项目最恨的失败方式：
不报错、不崩溃、日志一片祥和。

### 解法：实例探针 + 同步钩子

1. 车厢在铭牌里声明 `"实例缓存": ["翻译器"]`
2. 车钩在**任何实例被造出来之前**（`bridge.主()` 之前）把 `翻译器.__init__` 包一层，
   把所有实例登记进一个 `WeakSet`（类属性 `车钩活着的实例`）
3. 每次换轨之后，车钩调用每节车厢的可选钩子 `同步实例(bridge, 日志=)`
4. 动作面的 `同步实例()` 把活着的翻译器拉到当前的动作清单

**探针必须装在「编组没变就早退」之前** —— 否则「空车起车」这条路上探针永远装不上。

由 `测车钩.py` 的 I 组专门验（热挂之后，**已经存在的**那个实例的 `合法步骤`
必须从 10 变 13；热摘之后必须收回去）。

### 顺带解决的第二个问题

`忙不忙()` 也要看**实例**（`任务` 是实例属性，类上没有）。
所以摘车厢之前会扫所有活着的任务栈实例，任何一个在忙就算忙 → 拒绝摘除。

## 七、开发中踩到的坑（都写进测试了）

| 坑 | 现象 | 修法 |
|---|---|---|
| **回退卸错了对象** | 换轨失败时调 `_全卸()`，而它读 `self.编组` —— 那还是**旧名单**，刚打上去的越权补丁**一个都没被卸下来** | 新增 `_卸这些(已挂)`，`已挂` 单独记；而且要**先记账再挂**（`装上()` 可能打了一半才抛） |
| **体检时用的是旧名单** | 挂动作面被误判成「偷偷扩权」 | `宪法体检(名单)` 加参数，换轨时传新名单 |
| **同名类被模块级变量遮住** | `列车 = None` 把 class `列车` 遮住 → `TypeError: 'NoneType' object is not callable` | 删掉那行 |
| **解析器忘了调用** | `参 = argparse.ArgumentParser(...)` 之后没 `parse_known_args()` | 改成 `ap = ...` + `参, 剩下 = ap.parse_known_args()` |
| **两节车厢的 `补丁.py` 撞名** | `import sys.modules` 里互相顶掉，摘的时候会摘到"不是它"的对象 | 按文件路径载入，模块名带车厢 id |
| **测试污染** | `测车钩.py` 把真的 `外挂/编组.json` 写成了「空车」，下次起车莫名其妙 | 测试里重定向 `车钩.编组文件` 和 `车钩.插座路径` |
| **裸字符串会炸主链** | 摘掉受限脚本之后往 `接()` 塞一段字符串 → `AttributeError`（`bridge.py:1449` 假设 step 是字典） | 主链**既有**的脆弱点，生产路径走不到；测试里用 `试接()` 把异常当结果收下 |

## 八、受限脚本车厢

灵感来自 Numen（言出法随）让大模型**写 Lua 程序**一次干几十步。
但我们**不走沙箱解释执行**，走的是**静态展开**：

```
剧本（分行文本）  →  静态检查  →  展开成扁平的步骤表  →  走原来的 fail-closed 闸
```

**循环在接单之前就被拆开，`i` 在展开时就被代成具体数字。**
校验器看到的 = 真正会跑的，一个字节都不差。

### 语法

```
# 井号开头是注释
走到 100 64 -200
挖 100 64 -200
说 我去挖矿了
拾 物品=cobblestone
合成 物品=crafting_table 数量=1
箱子里取 100 64 -200 物品=cobblestone 数量=10
往箱子里放 100 64 -200 物品=cobblestone 数量=5
熔炉放料 100 64 -200 输入=raw_iron:3 燃料=coal:1
熔炉取成品 100 64 -200

重复 5 次 记作 i {
  挖 100+i 64 -200
  走到 100+i 64 -199
}
```

坐标可以写 `起点 起点 起点`（从自己的位置算起）。
坐标里的算式只认四种：`3`、`i`、`3+i`、`3-2*i`。**没有条件判断、没有变量计算。**

### ⚠ 它带的新攻击面，以及怎么堵的

主链的 `任务栈.接()` 只查「动作在不在 `允许动作` 里」，
而 **「打」就在允许动作里**（`bridge.py:1372`）。
平时拦住「打」的是它上游的**翻译器**（`翻译器.禁止步骤 = {"打"}`）——
可剧本这条路**根本不经过翻译器**。

所以 `剧本.py` 必须自己补上这道闸，否则「剧本」就成了绕过宪法的后门：

```python
禁止动作 = 翻译器.禁止步骤 ∪ 翻译器.攻击类
```

**这个检查排在所有检查的最前面。** 顺序不能反 —— 如果先查「认不认识这个动词」，
那么等哪天有人把「打」加进规格表，这道闸就等于不存在了。

由 `剧本.py --自检` 的 B1/B2 和 `测车钩.py` 的 F6/F7 双份验证。

### 顺手修掉的老毛病

模型常常把「步骤」写成**字符串数组**（`["走到 1 2 3", …]`），
主链会回「第 1 步不是个对象」然后拒单。
既然剧本本来就是一行的文本，**一串字符串正好就是一段剧本** ——
受限脚本会把它拼起来当剧本展开。

展开不成功就**原样交回**给里面那层，行为跟以前一模一样（不因为修 bug 把拒绝路径搞丢）。

## 九、气隙设计：两节车厢怎么共存

车钩是**后挂的先执行**（栈）。所以：

- 动作面 `顺序=10`，受限脚本 `顺序=20` → 挂载顺序 `[动作面, 受限脚本]`
- 受限脚本是**最外层**：`接()` 先到它手里 → 展开剧本 → 再往下交给动作面的闸

两节车厢都是**包壳**（保存原函数、在里面调它），不是替换。
所以动作面那层「危险物品闸 + 参数完整性」照样会过，一道都不会少。

卸载时**逆序**，正好把包壳一层层剥回去。这就是全列重排为什么能保证干净。

## 十、加一节新车厢

1. `mkdir 外挂/我的车厢`
2. 写 `manifest.json`（最少要有 `id` / `名字` / `入口`）
3. 写 `补丁.py`：

```python
_原 = {}
_已装 = False

def 装上(bridge, 开关=True, 车钩=None, 日志=None):
    global _已装
    if not 开关:
        return {"好": False, "打了": [], "为什么": "开关关着"}
    if _已装:
        return {"好": False, "打了": [], "为什么": "已经打过了"}
    栈 = bridge.任务栈
    _原["接"] = 栈.接                    # ★ 一定要先存原件
    def 新接(self, 名字, 步骤, s):
        # ...你的逻辑...
        return _原["接"](self, 名字, 步骤, s)   # ★ 包壳：一定要调里面那层
    栈.接 = 新接
    _已装 = True
    return {"好": True, "为什么": "", "打了": ["任务栈.接() ← 我的改动"]}

def 卸下(bridge):
    global _已装
    if not _已装:
        return False
    if "接" in _原:
        bridge.任务栈.接 = _原["接"]
    _原.clear()
    _已装 = False
    return True
```

4. `python3 外挂/车钩ctl.py 列` 看它有没有被发现
5. `python3 外挂/测车钩.py` 确认没踩坏别的东西
6. 脑跑着的时候 `python3 外挂/车钩ctl.py 挂 我的车厢`

**三条铁律**：
- `卸下()` 必须**还原**（不是只 return True）
- 新增动作必须写进铭牌的 `提供动作`，否则宪法②会拦（这是故意的）
- 如果留了实例缓存，必须声明 `实例缓存` + 实现 `同步实例()`

## 十一、任务书体检 + 拒单反馈（2026-10-07 补的两节）

### 为什么要加这两节

2026-10-07 下午实机发现：**小家伙一次都没走出去过**。手侧日志一直在喊
`走不过去：p 得是三个数`，任务快照里写的却是：

```json
{"动作": "走到", "目标": "copper_ore(-38,50,-23)"}
```

模型把坐标写进了「目标」，而 `_下发()` 读的是 `步["p"]` → 发出去的是
`{"act":"goto","p":[]}` → 手当场拒收 → 重试 3 次 × 60 秒 → 失败 →
下个心跳模型再写一遍，**永远循环**。

★ 真正的窟窿在校验器：`翻译器._校验任务()` 只在 `p` **是列表且长度≥3**
  时才去查坐标。`p` 缺失 / 类型不对 —— 它一个字都不查。

### 任务书体检（顺序 30）

给 `翻译器._校验任务()` 包壳，加两道闸：

| 闸 | 内容 |
|---|---|
| ① | **不认识的字段** → 拒。这一条就抓住了「目标」/「坐标」这类乱起名 |
| ② | **必填字段缺失 / 坐标形状不对** → 拒 |

```
必填：走到/挖/放 → p    说 → 文本    熔炉放料 → p,输入,燃料
      熔炉取成品 → p     合成 → 物品   箱子里取/往箱子里放 → p,物品
```

**一票否决**：任何一步不合格，整份退回。
**缺坐标直接拒，绝不猜**（不会去 `"copper_ore(-38,50,-23)"` 里抠数字）——
主人 2026-10-07 定的规矩。理由：方块名里本身就可能带逗号数字，抠出来可能是
别人家的坐标；而且「猜」一旦开了头，下次「大概是这个意思吧」就挡不住了。

★ 挂在 `翻译器._校验任务()` 而**不是** `任务栈.接()` 上：
  接() 只回一个 `bool`，拒单原因就丢了；`_校验任务()` 回
  `(好, 原因, 干净)`，原因能一路传出去。

★ 主链自己的检查**先跑**：它拒了就原样返回它的理由 ——
  免得把「任务书里不许有『打』」这种宪法级提示盖成一句干巴巴的「缺 p」。

★ 「认识字段」那张表是**从主链代码 grep 出来的**，不是拍脑袋写的：

```bash
grep -oE '步\.get\("[^"]+"|步\["[^"]+"\]' bridge.py | sort -u
grep -oE '步\.get\("[^"]+"' 外挂/动作面/补丁.py | sort -u
```

主链读了新字段就得跟着加 —— **加漏了会误退合法任务书**，这是它唯一需要
维护的地方。

### 拒单反馈（顺序 40）

光拒不行：模型只能**盲改**。主链其实把原因记下来了
（`bridge.py:2843` 的 `{"事件":"被校验拒了","原因":…}`），但只进账本、
**不回 prompt**。于是模型唯一的反馈是「连续失败 2 次」——
知道「我错了」，不知道「我错在哪」。

两件事：

1. 包 `翻译器.收输出()` —— 原因非空就记下原因 + 模型当时的原文；成功就清账
2. 包 `翻译器.组Prompt()` —— 把旧账念叨回去：

```
【★ 你上一次交上来的东西被退回来了，先看这个再动手】
  · 退回原因：第 1 步「走到」里有**不认识的字段**：坐标；它需要 p。
    正确写法：走到(p=[x,y,z], 到点=2.5)。字段名必须和规格一模一样…
    你当时写的是：{"任务":{..."步骤":[{"动作":"走到","坐标":[-38,50,-23]},…
  请照上面的原因改好再交一次。
```

**节流**：只念叨 15 分钟以内的记录；每类最多 2 条；整段硬顶 600 字。

★ 顺序 40 排最外面 —— 它调完里面几层的 `组Prompt` 才追加自己的，
  所以动作面和受限脚本写进 prompt 的内容一个字不少（测试 C6 专门守这条）。

### 实机效果（2026-10-07 傍晚，当天就跑通了）

```
18:23  模型写字符串数组 → 拒「第 1 步不是个对象」
18:24  反馈喂回去（prompt 1626 → 1845 字）
18:25  模型改成对象了，但字段名写「坐标」→ 拒（车体检抓住）
18:25  反馈再喂回去 → 空转两次，退避 5 分钟
18:30  ★ 模型写对了：{"动作":"走到","p":[-38,50,-23],"到点":2.5}
18:30  接单成功，第一步「走到」通过
```

**三轮之内模型自己改对了。** 而且验出它之前的另一个真相 ——
第二步 `挖` 失败的真实原因是 `我手里没有镐子，挖不了「copper_ore」`。

### 顺带验出来的：它本来就会走路

同一天用 RCON 代 mintstar 在游戏里说「去 -30 50 -21」：

```
[18:32] 听懂了：「去 -30 50 -21」→ goto
[18:32] 他动了，挪到 (-34, 50, -19)（走了 4.0 格）
[18:32] 走不过去：这条路被新命令打断了，重新算
[18:32] 他动了，挪到 (-31, 49, -20)（走了 3.3 格）
```

两跳共 **7.3 格**，最后停在离目标 1.4 格处（在 2.5 的到点半径内）。
**寻路、抬腿、跳一格台阶全都是好的** —— 之前走不了纯粹是任务书格式错。

### 「跳」的两层真相

| | 结论 |
|---|---|
| **主动跳** | **没有。** 手侧有 `jump` 命令（`proto_body.js` 的 `跳跃()`），但脑的两份清单（`任务栈.允许动作` / `翻译器.单步白名单`）里都没有它 —— **脑没有任何路能调到它**。`sneak` / `swimdown` / `use` 同样情况 |
| **被动跳** | **会。** mineflayer 寻路器自己会在需要跨一格台阶时抬腿：`lib/movements.js:447` 有一档专门的「跳上一格」走法（cost 2 = move+jump），`index.js` 执行时真的按跳跃键。**但只跳一格**（高度差 `> 1.2` 就判「太高，跳不上去」） |

手侧一共认识 12 种命令（`sneak jump jumpattack swimdown dig place craft use
furnace_put furnace_take chest_take chest_put`），脑只能发出其中一部分。
**这是一份现成的「还没接线」的清单。**
