# M5/M6 草案 · 双向翻译器与三觉建设（自主玩伴）

> 一句话题目：**给它装上"听觉、视觉、触觉"，再给它一颗会自己想事的心 ——
> 让它从"翻译指令的机器"变成"会自己找事做的玩伴"。**

主人 2026-10-01 的原话：
「M4c 只是它的手脚，没有感知它就无法自主。现在正式开启 M5/M6 架构：双向翻译器与三觉建设。
让 LLM 能自主生成任务，而不仅是翻译指令。」

---

## 一、目标与非目标

**目标**
1. **三觉上行**：把"世界、话、身体"翻译成 LLM 能读懂的文字（视觉 / 听觉 / 触觉）。
2. **双向翻译器**：上行组 Prompt；下行把 LLM 的**宏观规划**翻成 **M4c 任务书**，
   并且逐条过 fail-closed 校验。
3. **自主心跳**：低频循环里，没任务在执行时，LLM 依据三觉自己定一个小目标。

**非目标（这一轮明确不做，免得摊子铺太大）**
- 不做"截图喂多模态模型"那种视觉 —— 只给**结构化文字**（省 token、可复现、可审计）。
- 不让 LLM 直接控制手：**一切动作必须经过 M4c 任务栈**（主人的硬要求）。
- **LLM 永远不许生成「打」步骤**（攻击权只在反射层/猎手手里，见 §六红线）。
- 不做长期记忆/人格演化（那是 M7 的事）。

## 二、总体架构（数据怎么流）

```
                  ┌─────────────── 手（只报事实，不做判断）───────────────┐
                  │  既有：血量/饥饿/威胁/玩家/掉落/三条探针/stuck/死亡…   │
                  │  新增：scan_environment（时间·天气·群系·资源·实体）      │
                  │        聊天原文（已经有的 event.chat）                  │
                  │        装备耐久（held + 四件护甲）                      │
                  └────────────────────────┬───────────────────────────────┘
                                           ↓  结构化事实
                 ┌═════════════ 三觉（M5.1/5.2/5.3）═════════════┐
                 │ 视觉：世界长什么样（scan_environment 摘要）    │
                 │ 听觉：谁在说什么（最近 N 条 + 是不是指令）      │
                 │ 触觉：我身体怎么样（疼/饿/装备快坏/卡住…）      │
                 └────────────────────┬───────────────────────────┘
                                      ↓
                 ┌══════════ 双向翻译器（M5.4）══════════┐
                 │ 上行：三觉 + 人格 + 规矩 + 任务状况      │
                 │       → System Prompt / Context        │
                 │ 下行：LLM 输出 → fail-closed 校验 →     │
                 │       ① 白名单单步动作 ② M4c 任务书      │
                 └────────────────────┬───────────────────┘
                                      ↓
                    ┌───────── 云端 LLM（deepseek-chat）─────────┐
                    │  输出严格 JSON：{"act":…} 或 {"任务":{…}}   │
                    └────────────────────┬───────────────────────┘
                                      ↓
                 指令层 / M4c 任务栈（+ 心跳在没任务时点火）
                                      ↓
                  反射层 —— **永远最高优先级，一票否决**（M1~M4b 一行不改）
```

**分工纪律（沿用整条线）：手只报事实，脑只做判断，翻译器只做翻译，
校验器只做放行/拒绝 —— 谁都不许越界。**

## 三、M5.1 视觉上行：`scan_environment`

**接口**（手侧新增一个动词，纯读、不动世界、不花服务器）：
```
{"cmd":"scan_environment","半径":12,"步长":2}
→ 回执 + 快照里给 `scan` 字段（下面这份结构）
```
**给什么**（全都是**已核实**的 API，不是我猜的）：
| 项 | 来源 | 例 |
|---|---|---|
| 游戏内时间/昼夜 | `bot.time.timeOfDay`（0~24000） | 「第 3 天 · 深夜（18000）」 |
| 天气 | `bot.isRaining` / `bot.thunderState` / `bot.rainState` | 「雷雨」 |
| 我在哪 | `pos` + `blockAt(脚下).biome.name` | 「在平原，站着 (12,78,-3)」 |
| 地形概况 | 半径内**抽样**方块（默认步长 2）统计 | 「石头 84、泥土 31、水 12、原木 4」 |
| 可交互方块 | 工作台/箱子/熔炉/床/门（有名有坐标，最多 6 条） | 「熔炉 (20,78,-20)」 |
| 附近实体 | 玩家（名字/距离/血量若有探针）、敌对（种类/数量/最近距离）、动物、掉落物 | 「僵尸 ×2，最近 9 格」 |
| 危险 | 半径内岩浆/水/悬崖边（沿用手里已有的 `前方危险` 判据） | 「东边 6 格有岩浆」 |

**预算与红线（这一节是硬约束）**
- **一次扫描 ≤ 20 行 / ≤ 600 字**（超了就只报"最多的前 8 类"）。
- 半径默认 12、**步长 2**（≈1.8 千次方块查询，客户端本地读，几毫秒级）。
- **按需扫描**：只在①主人问「看看周围」②M6 心跳点火 ③任务开始前 —— 三种时机之一。
  **绝不每帧扫**（CPU 红线在那儿）。
- 输出分两份：`scan.结构化`（给翻译器拼 prompt）＋`scan.一句话`（给人看的日志）。

## 四、M5.2 听觉上行：听得懂"人话"，也听得见"闲话"

**现状**：聊天已经有 event 流进来；指令层认得出 11+8 条句型；
认不出的、而且大模型开着，才会问一次 LLM（M3 就有的路）。

**M5 要补的**：
1. **闲聊通道**：认不出 ≠ 听不懂 —— 主人说「今天好累啊」，它应该**回一句人话**，
   而不是"这句我没学过"。
2. **上下文窗**：给 LLM 最近的 **6 条**聊天（谁+内容+多久以前），
   不至于答非所问。
3. **防刷屏（硬规矩）**：同一人两次之间 ≥ 5 秒；全局 ≤ 6 句/分钟；
   自己刚说过的话不许重复（相似度去重）。
4. **谁能闲聊**：默认只跟**主人和好友名单**里的人聊（`m5.chitchat.allow_from`），
   陌生人说话只记录、不搭话。
5. **指令优先**：能当指令听懂的一律走指令层/任务栈，**绝不因为闲聊把活儿打断**。
6. **决不在打架/逃命/低头干活时闲聊**（反射层不是平静就不接话）。

## 五、M5.3 触觉上行：把事实翻译成"感受"

LLM 不需要知道 `hp=9.4 food=7 stuck_ms=320` —— 它需要知道「**我有点疼，肚子也饿**」。
所以这一层是**规则 + 阈值**的转换器（配置可调，输出样例固定）：

```
【我现在的感受】
· 有点疼（血 9/20），肚子饿（7/20），背包里有 3 块牛排 —— 我想吃点东西
· 手里的铁剑快断了（用了 87%），四件护甲里胸甲磨损最狠（71%）
· 背包 31/36 格，快满了；没带火把
· 刚才在山坡那儿卡住了两次（想往东北走，走不动）
· 天黑了（第 3 天深夜），身上没有光源
```
**感受清单（第一版就做这些）**
| 感受 | 判据（事实） | 给 LLM 的提示 |
|---|---|---|
| 疼 / 快不行了 | 血量档位（<50% / <25%） | 该吃/该躲 |
| 饿 / 饱 | `food` 档位 + 背包有没有吃的 | 该吃/该打猎 |
| 装备快坏了 | `durabilityUsed/maxDurability` ≥ 80% | 该换/该收手 |
| 背包快满了 | 已用格数 ≥ 32/36 | 该回家放东西 |
| 手头没工具 | 探针里没有镐/剑 | 该去做/该要 |
| 卡住了 | `stuck_count` 在涨 | 该绕路（M4b 已能处理） |
| 谁打我 | `attacked_by` | 该应战/该跑（反射层已处理） |
| 天黑了没光 | 时间 + 背包没有火把 | 该点灯/该回家 |
| 没事干 | 没有任务 + 平静 ≥ 60 秒 | 这是心跳点火的信号 |

**需要手侧补的事实**：`durability`（held + armor 四件，用 `item.durabilityUsed/maxDurability`✓）、
`背包格数`（已核实：`bot.inventory.items()` 可数）。其余都是现成的。

## 六、M5.4 双向翻译器：唯一的出入口

### 上行（事实 → Prompt）
拼装顺序（**总长 ≤ 1200 字**，超了先砍视觉细节、再砍听觉）：
```
① 你是谁（人格卡要点，30 字）
② 铁规矩（不能直连攻击；一切动作经任务栈；看不懂就输出 {}）
③ 三觉 Context：视觉摘要 / 最近聊天 / 我的感受
④ 现在的状况：任务栈在第几步、剩几步、反射层在干什么
⑤ 你要输出的东西：严格 JSON，二选一
   {"act":"goto","p":[x,y,z]}                     ← 单步（白名单内）
   {"任务":{"名字":"…","步骤":[…],"预期秒数":60}}   ← 任务书（≤6 步）
```

### 下行（LLM → 安全动作）：**fail-closed 校验器**
**逐条拦住**（任何一条不过 → 整个输出作废 + 记账 + 什么都不做）：
1. 不是严格 JSON / 夹了 markdown 代码块 / 有解释文字 → 拒。
2. `act` 不在白名单（`follow/goto/say/stop/status/friend`）→ 拒。
   **攻击类永远不在白名单里。**
3. `任务` 的每一步 `动作` 必须在 M4c 的 `允许动作` 清单里 → 否则拒（复用同一份清单，
   不许两边各写一套）。
4. **任务里不许有「打」步骤** —— LLM 连间接指定攻击目标都不许；
   要打只能由反射层/猎手根据"敌对名单"自己决定。（主人：仍然不许直连攻击。）
5. 坐标越界 → 拒：离我 > 64 格、或 y 不在 (世界底, 320)。
6. 数量越界 → 拒：单任务 ≤ 6 步、数量 ≤ 64、不给"挖一片区域"这种无限指令。
7. 危险动作 → 拒：不许挖 bedrock/barrier 那一类（复用 `挖不动` 表）、
   不许放熔炉外的容器操作（这一轮只有熔炉）。
8. 冷却与预算：≥10 秒一次、≤40 次/小时（沿用 M3 的老规矩）+ 心跳另有预算。

**审计**：每次调用把 `prompt 摘要 / 原始输出 / 校验结果 / 拒绝原因` 全写进
`logs/llm审计.jsonl`（老规矩），心跳额外写 `logs/心跳.jsonl`。

## 七、M6 自主心跳：没活干的时候，它自己找活

**点火条件（全部满足才点）**
1. `m6.heartbeat.enable = true`（**默认 false**，先在验收里打开）。
2. 反射层**平静**（没有打架/逃命/挨饿）+ 任务栈**空闲**。
3. LLM 开着，且距上次心跳 ≥ `心跳秒`（默认 **60 秒**，不是 30 —— 见 §八预算）。
4. 最近 20 秒没人跟我说话（别抢话）。
5. 主人在线（`players` 里有主人）—— 主人不在就安静待着，别自己刷 API。

**它收到什么**：三觉 Context + 「现在没有任务。你可以：① 什么都不做（输出 `{}`）
② 给自己定一个小目标（输出任务书，≤6 步，别跑远、别碰主人的东西）。」

**护栏（护栏比功能重要）**
- 任务**必须**过 §六 校验器；**不许有打步骤**；不许动玩家的箱子/建筑。
- **空转保护**：连续两次心跳生成的任务都当场失败 → 心跳退避 5 分钟（别钻牛角尖）。
- **别打扰主人**：心跳生成的目标里最多 `say` 一句；不追着主人跑（`player_near` 只用来看）。
- **红线优先**：热保护一挂起，心跳立刻停；反射层一接管，任务照旧暂停。
- **可停**：主人一句「别自己找事」→ `m6.heartbeat.enable=false` 并记账。

**验收用的三个典型场景**
- 「天黑了，去砍树/挖石头（附近有）」→ 任务书：走到 → 挖 → 拾 → 回来。
- 「血少又饿，背包有牛排」→ 先吃（`eat` 走反射层），再决定要不要回家。
- 「背包快满了」→ 走到箱子（若有）或说一句「我背包满了，得找个地方放东西」。

## 八、成本与红线（主人最在意的部分）

| 项 | 默认 | 说明 |
|---|---|---|
| 心跳频率 | **60 秒**（不是 30） | 只有"平静+空闲+主人上线"才点，实际多半更稀 |
| 上行 prompt | ≤ 1200 字（≈ 600~800 token） | 超了先砍视觉细节 |
| 心跳预算 | ≤ **30 次/小时**、≤ 300 次/天 | 超了就静默到下一小时 |
| 闲聊 | 按人来（有人说话才回） | 同人 ≥5 秒、全局 ≤6 句/分 |
| 预估 token | 心跳满打满算 ≈ 2 万 token/小时 | 审计日志里能按小时统计（我会先给一份估算） |

**红线不变**：CPU ≤ 60%、温度上限、内存上限、**不推远程仓库**、
所有动作经任务栈、反射层一票否决、`tools/安全检查.py` 全过
（并新增两条断言：**"翻译器里没有攻击类白名单"**、**"任务书校验器拒绝『打』步骤"**）。

## 十、开关与回滚

| 开关 | 默认 | 关掉之后 |
|---|---|---|

## 十一、我想先跟主人确认的三个点

1. **心跳默认关还是开**？我建议**默认关**（验收时开），跑顺了再设 `true` —— 省 token、稳。
2. **心跳频率 60 秒**（而不是 30 秒）你接受吗？30 秒的 token 成本大约是 60 秒的两倍
   （满打满算 ≈ 4 万 token/小时）。
3. **闲聊范围**：只跟"主人 + 好友名单"聊，陌生人只记录不搭话 —— 够用吗？
   还是你想让它对谁都搭一句话？
