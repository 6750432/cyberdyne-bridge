───────────────────────────────────────────────────────────────
零、先把 M7b 拆成两半（关键）
───────────────────────────────────────────────────────────────

  M7b「动作面」= 合成 / 从箱子拿 / 往箱子里放。它天然是两半：

  【手侧】真去开箱子、真去合成的那只手
      → **已经在插件里了**，`node/plugins/body/proto_body.js`：
        · 危险物品 名单
        · 找箱子() / 箱子里取 / 往箱子里放 三个能力
        · 能力表里登记 chest_take / chest_put
      → node/server.js 的动词表（case 'move' / 'eat' / …）**一个 case 都没加**，
        走的是插件挂载点那条既有分支。**这半边已经符合 M2 规矩了。**

  【脑侧】小家伙得"知道自己有这三种本事"、听得懂口令、写得进任务书
      → 这才是唯一的难点：**bridge.py 里没有插件位。**
        任务栈 / 三觉 / 翻译器 / 心跳 / 记忆 全是 M4c–M7a 直接写进去的类。
      → 所以问题其实是一句话：**怎么给一个没有插件位的 Python 主链加本事？**


───────────────────────────────────────────────────────────────
一、我的建议：外挂式（运行时打补丁，bridge.py 零改动）
───────────────────────────────────────────────────────────────

  目录：

    ~/cyberdyne-bridge/
    ├── bridge.py                    ← ★★ 一个字不改 ★★
    ├── tools/启动大脑.sh             ← 也不改（保持基线那个入口原样）
    └── 外挂/动作面/
        ├── 大脑外挂.py               ← 入口：import bridge → 自检 → 打补丁 → bridge.主()
        ├── 启动.sh                   ← exec nice -n 15 ionice -c3 python3 -u 大脑外挂.py
        ├── 补丁.py                   ← 三类补丁都在这儿（任务栈 / 指令层 / 翻译器）
        ├── 自检.py                   ← 启动前逐条查"锚点还在不在"
        ├── 测动作面.py               ← 新写的断言（**不动** tools/ 里那六套）
        ├── data/items_map.json       ← 物品口语名 → MC 名（外置，主人点名要的）
        └── prompts/                  ← prompt 片段（外置，主人点名要的）
            ├── 步骤清单.txt
            ├── 动作词表.txt
            └── 危险物品.txt

  大脑外挂.py 干四件事，顺序不能乱：

    ① import bridge                    （只 import，不触发 主()）
    ② 自检：要挂的锚点逐条查一遍
         类名 / 方法名 / prompt 里那几句关键话
         ★ 任何一条对不上 → **拒绝启动**，打印"缺了什么、在哪一步"
    ③ 读 config.json 的 m7.expand_actions
         false → **一个补丁都不打**，直接 bridge.主()（行为 = 基线，逐字节相同）
         true  → 打补丁
    ④ bridge.主()

  开关的住处仍然是 config.json 的 `m7.expand_actions`（唯一出处，不在别处再存一份）。
  回退：**不启动外挂 = 基线**；要彻底回退就 `git reset --hard 基线-M1-M7a`。

───────────────────────────────────────────────────────────────
三、为什么推荐它
───────────────────────────────────────────────────────────────

  1. 主链零改动，而且**这件事可以机器验证** ——
     `git diff 基线-M1-M7a -- bridge.py` 输出为空。不用我嘴上保证，随时能查。

  2. 开关关着时行为 = 基线：补丁代码**根本不加载**，不是"加载了但跳过"。

  3. 自检是 fail-closed 的，专治这个项目最怕的失败模式：
     主链将来改了名，外挂**当场拒绝启动**并说清缺什么，
     而不是"悄悄不生效"—— 后者比崩掉危险得多（M7 那次 availableGeometry()
     返回 0×0 导致一个像素都画不出来、日志却一切正常，就是这类）。

  4. 外挂坏了不牵连主链；不想要了把 `外挂/` 删掉就干净了。


───────────────────────────────────────────────────────────────
四、代价（得先说明白，别到时候说我没讲）
───────────────────────────────────────────────────────────────

  1. **靠主链的内部名字活着**（`bridge.任务栈.允许动作`、`翻译器.组Prompt` …）。
     主链哪天重构改名，外挂就断了 —— 有自检兜着，是"断"不是"错"。
  2. **会有一点逻辑重复**：判据、组 prompt 的那几行外挂得自己写一份。
     防漂移的办法：外挂的断言里加一条"我的判据跟主链基线一致"的对照。
  3. **调试时"代码不在你以为的那个文件里"** —— 看调用栈得记得有外挂这一层。
  4. 运行时打补丁属于"魔法"。所以外挂目录里必须有一份 README 说清
     "为什么改了 config 就多出三种本事"，否则后来者看不懂。

五、备选方案（我不建议现在做，但摆出来）
───────────────────────────────────────────────────────────────

  【正式立一个脑侧插件位】在 bridge.py 里加一个 `brain_plugins/` 扫描 + 挂载点。

    · 好处：正统、干净、"主链只放接线"贯彻到底。
    · 为什么先不做：**这条路本身就要动主链**（至少加一个 loader），
      而 loader 的接口长什么样是**架构级决定**，不该在一轮功能开发里顺手拍。
    · 我的建议顺序：**外挂先跑通、拿到真实使用数据 → 攒够了再回来说
      "要不要把插件位正式化"**。那时候改主链是"有数据支撑的架构决定"，
      不是"写着写着顺手加进去"—— 后者正是这次挨骂的原因。

七、两个我踩过、这次必须一开始就设计对的地方
───────────────────────────────────────────────────────────────

  ① 「把 3 个 X 放进箱子」的判据不能只看数量
     如果判据是"背包里 X ≤ 保留数"，那"把 3 个放进箱子"会被错判成
     "把 10 个全放光"，永远判不完。
     正确：**开工那一刻先记下存货当基准**，判"比基准少掉至少 N 个"；
     写了「保留」才用"≤ 保留数"。
     （这是 2026-10-02 设计时发现的，写在这里免得重蹈。）

  ② 坐标提取会被数量词污染
     坐标是按"三连数字"抓的，「把 3 个石头放进箱子 21 78 -21」会被读成
     坐标 (3, 21, 78)。必须先抠掉「3 个」这类数量词，再提坐标。
     （同样是离线自测当场抓到的，撤销报告里记过。）

  另外：「火把」的「把」不能当量词删，"见把就删"会把「火把」删成「火」。
  这类中文坑，第 2 步的词表校验要能挡住。
