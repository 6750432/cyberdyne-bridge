# Cyberdyne-Bridge · 开发宪法

> 这不是"建议"，是**踩出来的规矩**。每一条后面都写着它是怎么来的 ——
> 因为它们全都是"犯过一次、代价不小"才写进来的。
>
> 立宪日期：2026-10-01　维护：大肥鱼（AI 助手）+ 主人（人类，最终验收）

---

## 第〇条 · 总纲

**主链只放接线，新能力全部外置。**
主链 = `bridge.py`（脑）、`node/server.js`（手）、`config.json`（配置）。
新能力进 `node/plugins/<名字>/`（手侧）或 `外挂/<名字>/`（脑侧）。

判定"改动是否合法"，**不看我说什么，看 git**：

```bash
git diff 基线-M1-M7a -- bridge.py     # 输出必须为空
sha256sum bridge.py                   # 必须是 2499f81f807431b0…
git status                            # 必须干净
```

## 第一条 · 不许直接攻击

LLM 不能"直接攻击"任何人 —— 它没有这个能力，也不许绕弯子去要。
攻击权只在反射层 / 猎手手里（按敌对名单自己决定）。

落实：`翻译器.禁止步骤 = {"打"}`、`翻译器.攻击类 = {attack, jumpattack, strike, 打击}`，
且单步白名单与攻击类**不许有交集**。`自检.py` 每次启动都验这三条还在。

## 第二条 · 任务书里不许出现「打」

LLM 生成的**多步任务**里，任何一步都不能是「打」。出现即**整份作废**。

落实：见第一条那三个集合。

> ★ 注意这条的**衍生结论**（2026-10-01 被自己的断言揪出来的）：
> `prompt 动作词表 = 任务栈.允许动作 − 翻译器.禁止步骤`
> 主链允许动作有 10 个（含「打」，反射层要用），但发给 LLM 的只有 9 个。
> 我第一版把等式写成"完全一致"，当场报错 —— **两个集合不是一回事**。

## 第三条 · fail-closed：拿不准就拒绝

听不懂、锚点对不上、参数缺、名字认不出来 —— 一律**拒绝执行 + 记一笔账 + 说人话**。
绝不"猜一个动作出来"、绝不"凑合能用"。

推论：**「悄悄不生效」比「当场崩掉」危险得多。**
（2026-09-29 那次 `availableGeometry()` 返回 0×0，一个像素都画不出来，
而日志里"重绘 47 次、每次 25 ms"一切正常。静默失败是最贵的失败。）

## 第四条 · 测试通过 ≠ 测试有意义

一个**从来不会失败**的校验，等于没有校验。

落实：每条关键校验都要配**反向测试** —— 故意喂坏数据，看它会不会真的报错。
（`测数据.py` 的 G 组 8 条、`测动作面.py` 的 L 组，都是这一条的产物。）

## 第五条 · 事实，不是猜测

完成判据一律**读探针事实**，不认"命令发出去了"。
没报错 ≠ 生效了。

推论：**二进制/数值能验的，就别靠肉眼。**
（"我说文件没被动过"不算数，`sha256sum` 前后一致才算数。）

## 第六条 ★★★ · bash 里一律用 ASCII 变量名

> **这一条是主人 2026-10-01 亲自点名写进宪法的。**
> 原话：「顺便把 中文变量名 这个坑写进你的开发宪法里，不许再踩第 N 次了喵」

**规则：bash 脚本里，任何标识符都必须是 ASCII。**
循环变量、`local` 变量、环境变量、普通赋值 —— 全都算。

```bash
模式="外挂"          # ❌ 错！bash 会把这整行当成"要去执行一个叫 模式=外挂 的命令"
MODE="外挂"          # ✅ 对
```

**为什么危险：它不报语法错，它只是"没生效"。**

```bash
在跑=$(ps ...)                     # ❌ 赋值失败，变量根本没设上
if [ -n "$在跑" ]; then ... fi      #   于是判据用了个空值 → 逻辑悄悄跑偏
```

### 犯案记录（全是真事，不是假设）

| 时间 | 现场 | 后果 |
|---|---|---|
| 2026-10-01 | `启动.sh` 里写 `在跑=$(...)` | **护栏变成"永远拒绝启动"的假阳性** —— 表面上"测试通过"，其实是坏的 |
| 2026-10-01 | `重启脑.sh` 里写 `模式="外挂"` | **`--看` 判假 → 本来只想看一眼，却把脑给停了**，小家伙当了 40 秒没脑的鱼 |
| 2026-10-01 | 我自己的临时测试命令里 `空=$(...)` | 命令直接 `command not found` |
| 更早 | `轮`、`假模型`、`串`、`改`、`新增`、`库`、`源`、`面宽`、`面高`、`时长`、`后端`、`模块`、`插槽`、`尺寸`、`日志`… | 反复踩，反复重写 |

**只影响 bash。Python / JavaScript 里中文变量名没问题**（整个 Cyberdyne-Bridge
的 Python 侧就是这么写的，而且可读性更好）—— 所以别把这条规矩带错地方。

### 配套的"加固动作"

光改名不够，还要**加兜底**：脚本对认不出的参数应当**直接退出**，
而不是落进"停进程 / 删文件"那条路。

```bash
case "$1" in
  "") MODE="外挂" ;;
  "--看") MODE="看" ;;
  *) echo "★ 不认识的参数：$1"; exit 2 ;;    # ★ 绝不因为参数看不懂就去停进程
esac
```

## 第七条 · ⚠ 动主链之前，先落快照

2026-10-01 的教训：随手改一个 4000 行的主链文件，**当时整个项目一个备份都没有**，
也不是 git 仓库 —— 出事神仙也救不了，连"回滚"都无从谈起。

现在的规矩：
1. `~/cyberdyne-bridge` 已经是 git 仓库，**基线钉在 `基线-M1-M7a` 标签上**。
2. 每过一个里程碑，打一个 `git bundle` 丢进 `~/cyberdyne-快照/`。
3. 改完**立刻 commit**；`git status` 必须干净。

## 第八条 · ⚠ 改了插件代码，必须重启对应进程

2026-10-01 实机验收抓到的：手进程 05:02 启动，`proto_body.js` 05:09 才加上
`chest_take`，于是手一直在回「不认识的命令「chest_take」」——
**箱子功能根本没到插件那儿**，而离线断言一条都测不出来。

**离线断言测不出"对面那个进程是不是旧的"。**
凡是改了 `node/plugins/**`，就必须重启手；改了 `bridge.py` / 外挂，就必须重启脑。

## 第九条 · 找进程不许只看 `ps` 的 args

同一天踩的：`ps -eo pid,comm,args | awk '$2=="python3" && /bridge\.py/'`
两个条件同时失效 ——
① 外挂跑的是 `python3 -u 外挂/动作面/大脑外挂.py`，命令行里**没有 `bridge.py`**；
② locale=C 时 `ps` 把中文路径显示成 `??????`，正则更匹配不上。

后果：启动器以为没脑在跑 → **同时起了三个脑抢同一个 socket**。

规矩：**认进程读 `/proc/<pid>/cmdline`**（原始字节按 utf-8 解），locale 影响不到。
`pkill -f` / `pgrep -f` 也一样危险 —— 它们会把调用它的那个 shell 自己杀掉（踩过三次）。

## 第十条 · 数据外置 + 加载时核对

词表、prompt 片段、物品映射一律放 `data/` 和 `prompts/`，**改文案不碰代码**。
但数据一离开代码就会**漂移**，而漂移**不报错**、只是静默地"看起来能用"。
所以加载时必须拿"真相"核对：

- 物品名 / 危险物品 → 拿 `minecraft-data` 的 `pc/<版本>/items.json` 逐条比
- 危险物品名单 → 必须跟**手侧插件里那份完全一致**（两道独立的闸，不许漂移）
- 动作词表 → 拿主链的 `任务栈.允许动作` 减 `翻译器.禁止步骤` 比

## 第十一条 · 中文语义坑（已固化成函数 + 反例证明）

| 坑 | 症状 | 规矩 |
|---|---|---|
| 「火把」的「把」 | 见「把」就删 → 「火把」变成「火」，查表查不到 | 抠数量词**只认「数字+量词」成对形态**，绝不单删一个「把」字 |
| 数量词污染坐标 | 「把 **3** 个石头放进箱子 21 78 -21」被读成坐标 (3,21,78) | 取坐标**之前**先抠数量词 |
| 物品名前后不定 | 「把 3 个 X 放进箱子 …」X 在前；「从箱子 … 拿 3 个 X」X 在后 | 按切点**取前/取后**，不能只顾一头 |
| 子串包含 | 「圆石」是「石头」…「火把」含「把」 | 危险物品一律**精确比较**，不做子串判断 |

★ 每条都配了**反例证明**（证明这坑是真的，不是瞎担心）：
见 `外挂/动作面/中文.py` 与 `测数据.py` 的 B/C 组。

## 第十二条 · 判据一律"相对开工基准"

「合成 3 个火把」若按"背包里有 ≥3 个"判，背包里本来就有 5 个时**第一拍就完成了**，
一个火把都没合成。「把 3 个石头放进箱子」同理会把"放 3 个"错判成"全放光"。

规矩：
```
合成 / 箱子里取   →  现在 ≥ 开工基准 + 数量
往箱子里放       →  现在 ≤ 开工基准 − 数量
```
基准**只在探针真的报了这件东西的数时才记** —— 宁可多等一拍，也不记一个假基准。

- 「说给某个对象听」的内容 → 单独 TXT 放 `~/米粒舊物倉/信件/`，聊天只留摘要 + 路径

- 验收报告必须写**失败和踩坑**，不只写成功
- 不推远程仓库 —— **除非主人明确要求**（2026-10-01 主人要求公开 Cyberdyne-Bridge，属明确要求）
